# 디자인

이 문서는 **시각 언어**만 다룬다. 데이터 경계·게이팅 규칙은 [plan.md](../plan.md), 화면 전이는 [USER_JOURNEY.md](./USER_JOURNEY.md), 컴포넌트 배치 규칙은 [ARCHITECTURE.md](./ARCHITECTURE.md)를 따른다.

## 1. 출처

`.claude/skills/finsight-design/` 스킬(Claude Design 산출물)의 디자인 시스템을 기반으로 한다. 규칙 전문은 스킬의 `README.md`에 있고, **이 문서는 TxAnalyzer에 맞춘 각색분과 원본이 답하지 않는 부분만** 적는다.

- finsight는 암호화폐 거래소 마케팅 브랜드다. **가져오는 것은 시각 언어(색·타입·간격·모양)뿐이고 브랜드명·카피·제품 자산은 가져오지 않는다.**
- 원본은 스스로 *"마케팅 표면만 다루며 로그인 뒤 화면은 범위 밖"*이라고 명시한다. TxAnalyzer는 대부분이 대시보드이므로 **§5의 신규 컴포넌트와 §8 차트는 우리가 정의한 확장**이다.
- 라이선스 서체가 없어 Inter(Display·Sans)와 JetBrains Mono가 대체로 들어가 있다. 교체 예정 없음.

### PRD와의 충돌 — 라이트로 확정

`PRD.md`는 *"다크 기반 미니멀"*, DS는 *"흰 캔버스"*다. **흰 캔버스를 기준으로 확정한다.** DS의 카드 채움·헤어라인·그림자 1단계가 전부 흰 바닥을 전제로 설계돼 있어, 반전하면 쓸 수 있는 규칙이 거의 남지 않고 다크용 텍스트·헤드라인 스케일을 새로 만들어야 한다. *"무채색 + 포인트 컬러 1가지"*라는 PRD의 나머지 절반은 그대로 유지된다.

> `PRD.md`의 "다크 기반" 문구는 **아직 수정되지 않았다.** 이 문서와 불일치한 상태다.

## 2. 원칙

1. **색은 하나뿐.** `#0052ff`. 한 밴드당 파랑은 1~2회만 쓴다 — 주 CTA, 워드마크, 인라인 브랜드 링크.
2. **숫자는 전부 Mono.** 정확한 값과 포맷으로만 쓴다. "약 6만원" 같은 표기는 없다.
3. **표면은 3종.** 흰색 · 연회색 · 풀블리드 근검정. 그라디언트·사진·텍스처·블러·반투명은 없다.
4. **그림자는 1단계.** 나머지 표면은 평평하거나 1px 헤어라인을 쓴다.
5. **이모지 없음, 느낌표 없음.** 빈 상태와 에러도 사실의 평서문으로 쓴다.

## 3. 토큰

값의 진실의 원천은 스킬의 `tokens/*.css`다. 아래는 TxAnalyzer에서 실제로 쓰는 것만 추린 것이다.

### 색

| 역할 | 변수 | 값 |
|---|---|---|
| 액션 | `--color-primary` | `#0052ff` |
| 액션 pressed | `--color-primary-active` | `#003ecc` |
| 액션 disabled | `--color-primary-disabled` | `#a8b8cc` (불투명 틴트, opacity 아님) |
| 캔버스 | `--color-canvas` | `#ffffff` |
| 연회색 면 | `--color-surface-soft` | `#f7f7f7` |
| 다크 밴드 | `--color-surface-dark` | `#0a0b0d` |
| 다크 위 카드 | `--color-surface-dark-elevated` | `#16181c` |
| 헤어라인 | `--color-hairline` / `-soft` | `#dee1e6` / `#eef0f3` |
| 잉크(제목) | `--color-ink` | `#0a0b0d` |
| 본문 | `--color-body` | `#5b616e` |
| 보조 | `--color-muted` / `-soft` | `#7c828a` / `#a8acb3` |
| 증감(텍스트 전용) | `--color-semantic-up` / `-down` | `#05b169` / `#cf202f` |

- **초록·빨강은 텍스트 색으로만 쓴다.** 버튼·칩 채움·행 하이라이트에 쓰지 않는다.
- `--color-accent-yellow` `#f4b000`은 원본에서 자산 그림자 일러스트 전용이다. **TxAnalyzer에서는 쓰지 않는다.**
- 두 번째 브랜드 색은 없다. 그라디언트도 없다.

### 타입

| 용도 | 크기/굵기/행간 | 비고 |
|---|---|---|
| Display | 80 · 64 · 52 · 44 · 36px / **400** | 자간 -2px→-0.5px. **굵게 쓰지 않는다** |
| Title lg / md / sm | 32/400 · 18/600 · 16/600 | |
| 본문 | 16/400/1.5 | 강조는 같은 크기 700 |
| 본문 sm / 캡션 | 14/1.5 · 13/1.5 | 법적·주의 문구는 캡션 + `--color-muted` |
| 배지 | 12/600 대문자 | 시스템에서 유일하게 대문자를 쓰는 곳 |
| 숫자 | 18/500/1.4 Mono | |
| 버튼 / 내비 | 16/600 · 14/500 | |

Display·Sans·Mono는 **한 줄 안에서 섞지 않는다.**

### 간격 · 모양 · 깊이

- 4px 배수: `4 · 8 · 12 · 16 · 20 · 24 · 32 · 48 · 96`. **주요 섹션의 상하 여백은 96px.**
- 콘텐츠 폭 1200px 중앙 정렬. 다크 밴드와 히어로만 풀블리드.
- 카드 간격 24px, 카드 안쪽 여백 32px.
- 반경: 조작 요소는 알약(100px), 컨테이너 24px, 중간 카드 16px, 입력 12px, 조밀한 행 8px, 인라인 태그 4px, 아바타·글리프 원형. **직각은 없다.**
- 그림자는 `0 4px 12px rgba(0,0,0,.04)` 하나뿐. 추가 단계·내부 그림자·글로우·색 그림자를 만들지 않는다.
- 테두리는 1px 한 종류. 유일한 2px는 입력 포커스 링(파랑)이다.
- 높이: 내비 64px, 버튼 44px(lg 56px), 입력 48px.

### Tailwind 연결

스킬의 `tokens/*.css`를 `app/globals.css`에 복사해 넣고 CSS 변수를 진실의 원천으로 둔다. Tailwind 테마는 그 변수를 **참조만** 한다. 값을 Tailwind 쪽에 다시 적어두면 두 벌이 갈라진다.

Tailwind 버전(v4 `@theme` vs v3 `tailwind.config.ts`)은 **step 0에서 결정한다.** `create-next-app`이 붙여주는 기본값을 그대로 쓴다.

## 4. 화면별 바닥과 구성

| 화면 | 바닥 | 구성 |
|---|---|---|
| 랜딩 `/` | 흰색 + 다크 히어로 | HeroBand(다크, 목업 카드 적층) → FeatureCard 3-up → PricingTierCard 2개 → CTABand → Footer |
| `/privacy`, `/terms` | 흰색 | 본문 한 단, 폭 720px로 좁힘 |
| `/login` | 흰색 | 중앙 카드 1장. Google 버튼 1개, 하단에 약관 캡션 |
| 대시보드 | 흰색 | 상단 내비 + 업로드 위젯 + 결과 5카드 |
| 히스토리 | 흰색 | 행 리스트, 헤어라인 구분선 |
| 리포트 상세 | 흰색 | 결과 5카드 |
| 설정 | 흰색 | 섹션별 카드, 계정 삭제는 맨 아래 |

**Pro 요금제 카드는 리본이나 색 테두리를 쓰지 않고 다크 표면으로 반전한다.** 이것이 이 브랜드가 "이것을 고르라"를 표현하는 방식이다.

대시보드는 마케팅 화면보다 조밀해도 된다. 원본 규칙 *"밀도는 로그인 뒤 화면의 몫이고 마케팅은 성기게 유지한다"*를 그대로 따른다 — 대시보드 섹션 간격은 96px이 아니라 48px을 쓴다.

**그대로 쓰는 것** — `Button` · `TextInput` · `BadgePill` · `Wordmark` · `TopNav` · `Footer` · `FeatureCard` · `HeroBand` · `CTABand` · `PricingTierCard`

**각색해서 쓰는 것**

| DS 원본 | TxAnalyzer | 바뀌는 점 |
|---|---|---|
| `AssetRow` | `TransactionRow` | 티커·시세 → 가맹점·날짜·금액·카테고리 |
| `PriceCell` | `AmountCell` | 상승/하락 → 지출 증감 (§6) |
| `AssetIcon` | `CategoryIcon` | 32px 원형 판, 채움은 `#eef0f3` 고정 |

**새로 정의하는 것 (DS 범위 밖)** — `DashboardNav` · `UploadDropzone` · `AnalysisProgress` · `StatCard` · `CategoryBreakdown` · `TrendChart` · `InsightCard` · `LockedTeaser` · `EmptyState` · `ErrorState` · `HistoryRow` · `UpgradeModal`

새 컴포넌트도 §3의 토큰만 쓴다. 새 색·새 그림자·새 반경을 만들지 않는다.

## 6. 금액과 숫자

- 전부 Mono. 예: `₩64,204` · `+2.4%` · `12,480건` · `2026-09-07`
- 금액은 원 단위 정수로 표시하고 소수점을 노출하지 않는다. 저장은 `numeric(14,2)`이고 표시만 반올림한다.
- 변화율에는 부호를 항상 붙인다.
- **증감 색은 finsight와 반대다.** finsight는 시세 상승이 초록이지만, TxAnalyzer에서는 **지출이 줄면 초록(`#05b169`), 늘면 빨강(`#cf202f`)** 이다. 기준은 시세 방향이 아니라 사용자에게 좋은 방향이다. 이는 원본 규칙의 의도적 확장이다.
- 색만으로 방향을 전달하지 않는다. 부호(`+`/`-`)가 항상 함께 간다.

## 7. 잠금(티저) 표현

서버가 응답에서 필드를 아예 빼기 때문에(`plan.md` §1) **UI는 "가려진 데이터"가 아니라 "없는 데이터"를 그린다.** 블러 처리한 실제 값이나 가짜 플레이스홀더 숫자를 그리지 않는다.

`LockedTeaser`는 연회색(`#f7f7f7`) 면에 총 건수와 한 줄 설명, 그리고 업그레이드 링크만 놓는다. 자물쇠 아이콘은 쓰지 않는다 — 이 시스템에는 아이콘이 두 개(돋보기, 체크)뿐이다.

## 8. 차트

DS에 차트 언어가 전혀 없어 여기서 정한다. 라이브러리는 step 10에서 정한다.

- **추이(단일 계열)**: 파랑 `#0052ff` 선 1개, 채움 없음, 점 없음. 격자선은 `#eef0f3` 가로선만.
- **카테고리 구성(다중 계열)**: 색상은 파랑 `#0052ff`의 **명도 단계 하나만** 쓴다. 두 번째 색을 도입하지 않는다. 항목이 6개를 넘으면 상위 5개 + "기타"로 묶는다.
- 축·범례는 14/500, 값은 Mono. 축 레이블은 회전하지 않는다.
- 숫자가 올라가는 애니메이션, 툴팁 바운스, 패럴랙스를 쓰지 않는다.

## 9. 상태

업로드는 `202 + uploadId`로 즉시 반환되고 분석은 백그라운드에서 진행된다. UI는 상태를 폴링한다(`plan.md` §3).

- **진행 중**(`queued|parsing|analyzing`): 스피너 + `"분석 중입니다."` 스켈레톤은 쓰지 않는다. 폴링이 2분을 넘기면 `"분석은 계속됩니다. 나중에 다시 확인하세요."`로 문구를 바꾸고 폴링을 멈춘다.
- **부분 완료**(`partial`): 해석만 실패한 상태다. 집계 카드는 정상 렌더하고 해석 카드에만 재시도 버튼을 둔다.
- **일부 행 누락**: `skippedRowCount`가 0이 아니면 결과 상단에 캡션으로 `"N행을 읽지 못했습니다."`를 둔다.
- **빈 상태**: 사실의 평서문 한 줄 + 주 CTA 1개. 일러스트 없음.
- **에러**: `message` 문자열이 아니라 `code`로 분기해 문구를 고른다.

| code | 문구 |
|---|---|
| `file_too_large` | 파일이 4MB를 넘습니다. |
| `invalid_file_type` | CSV 파일만 올릴 수 있습니다. |
| `empty_file` | 파일에 거래 내역이 없습니다. |
| `encoding_error` | 파일 인코딩을 읽지 못했습니다. UTF-8로 저장한 뒤 다시 올려주세요. |
| `parse_failed` | 파일을 읽지 못했습니다. |
| `column_mapping_failed` | 컬럼을 인식하지 못했습니다. 날짜·내용·금액 컬럼이 있는지 확인해주세요. |
| `mixed_currency` | 한 파일에 여러 통화가 섞여 있습니다. 통화별로 나눠서 올려주세요. |
| `unsupported_transaction_semantics` | 거래 유형을 구분하지 못했습니다. |
| `upload_limit_reached` | 이번 달 업로드 횟수를 모두 썼습니다. |
| `analysis_in_progress` | 이미 분석 중인 파일이 있습니다. 완료된 뒤 다시 시도해주세요. |
| `retry_limit_exceeded` | 재시도 횟수를 모두 썼습니다. |
| `analysis_timeout` | 분석 시간이 초과됐습니다. |
| `analysis_failed` | 분석에 실패했습니다. |
| `not_found` | 리포트를 찾을 수 없습니다. |
| `unauthorized` | 로그인이 필요합니다. |

## 10. LLM 텍스트 렌더

**AI 요약·인사이트·이상거래 설명은 Zod 검증을 통과한 뒤 플레인 텍스트로만 렌더한다.** 마크다운·HTML로 해석하지 않는다(`CLAUDE.md`, `plan.md` Global Constraints).

디자인상 의미: 해석 카드에는 **굵게·목록·링크·제목이 없다.** 단락 구분은 줄바꿈으로만 만든다. 여러 항목을 보여줘야 하면 마크다운 목록이 아니라 **배열 원소 하나당 컴포넌트 하나**로 렌더한다.

## 11. 한국어 카피

원본의 보이스 규칙은 영어 기준이라 그대로 옮길 수 없다. 다음만 가져온다.

- **차분한 금융 기관의 말투.** 다급하지 않고, 수익을 약속하지 않고, 조언하지 않는다.
- 사용자는 "회원님"이 아니라 문장에서 생략한다. 서비스 주체는 필요할 때만 "TxAnalyzer".
- 제목은 짧은 명사구나 서술형 한 문장. 문장부호·말장난·콜론을 쓰지 않는다.
- 버튼은 동사로 끝나는 2~5자: `시작하기` · `업로드` · `업그레이드` · `다시 시도`
- **이모지·느낌표·"앗!" 류의 에러 말투를 쓰지 않는다.**
- 피하는 표현: 혁신적, 손쉽게, 완벽한, 스마트한, 그리고 수익·투자 조언으로 읽힐 수 있는 모든 표현.
- 법적 고지는 숨기지 않고 캡션 크기로 항상 보이게 둔다. 특히 **거래 데이터가 분석을 위해 Anthropic API로 전송된다는 고지**를 가입·업로드 지점에 노출한다.

대문자 배지는 한국어에서 성립하지 않으므로, `BadgePill`은 한국어일 때 12/600 그대로 두고 대문자 변환만 뺀다.

## 12. 접근성

- 본문 대비 4.5:1 이상. DS가 반투명·알파 흐림을 쓰지 않는 이유가 이것이다. **텍스트에 opacity를 걸지 않는다.**
- 포커스는 2px 파랑 링. 지우지 않는다.
- 색만으로 정보를 전달하지 않는다(§6).
- 모든 입력에 라벨을 붙인다. placeholder로 라벨을 대신하지 않는다.

## 13. 정의하지 않은 것

원본이 문서화하지 않았고 우리도 지금 정하지 않는다. 필요해지는 시점에 이 문서에 추가한다.

- **호버 상태** — 원본이 의도적으로 비워둔 자리다. 필요하면 pressed 색(`#003ecc`)으로 어둡게 하고, 투명도 페이드를 새로 만들지 않는다.
