## 작업

`src/lib/analysis/`에 **코드 기반 집계 로직**을 구현한다. 순수 함수로 작성하고 테스트를 먼저 작성하라. 이 step에서 만드는 결과가 `AnalysisResult.payload.aggregates`가 된다.

1. **카테고리별 지출 집계** — 거래에 이미 부여된 `category`를 기준으로 합계·건수·비중을 계산한다. **분류 자체는 여기서 하지 않는다**(step 7의 LLM 담당). 카테고리가 없는 거래는 `기타`로 집계한다.
2. **기간별 지출 추이** — 월 단위 합계 시계열을 만든다. 거래가 없는 달은 0으로 채워 연속된 시계열이 되게 한다.
3. **반복 결제 후보 탐지** — 동일 `merchant_normalized`에 대해 금액이 유사하고 결제 간격이 주기적인(월/주 단위) 거래 묶음을 찾는다. 각 후보에 대해 가맹점, 주기, 평균 금액, 발생 횟수, 마지막 결제일을 반환한다. **"이상"인지 여부를 판정하는 자연어 설명은 붙이지 않는다**(step 7 담당).
4. **요약 통계** — 총 지출, 거래 건수, 분석 기간, 일평균/월평균 등 LLM 해석 단계에 입력으로 넘길 수치를 만든다.

**모든 금액 계산은 정밀도를 보존해야 한다.** 부동소수점 누적 오차로 합계가 틀리면 안 된다. 합계 검증 테스트를 반드시 포함하라.

## Acceptance Criteria

```bash
npm run build
npm test
```

테스트는 최소한 다음을 포함해야 한다: 카테고리 합계가 총액과 일치, 빈 달이 0으로 채워진 시계열, 월 구독 패턴 탐지, 주기성이 없는 거래는 후보에서 제외, 소수점 금액 누적 시 오차 없음, 거래가 0건일 때.

## 검증 절차

1. 위 AC 커맨드를 실행한다.
2. 체크리스트:
   - 외부 I/O나 LLM 호출이 전혀 없는가?
   - 합계·평균이 부동소수점 오차 없이 계산되는가?
   - 반환 타입이 step 2의 `aggregates` 타입과 일치하는가?
3. `phases/0-mvp/index.json`의 step 4를 업데이트한다. `"summary"`에 export한 함수 시그니처를 남겨라.

## 금지사항

- Claude API를 호출하지 마라. 이유: 이 step은 결정론적 집계만 담당한다. 금액 산술을 LLM에 맡기면 환각으로 합계가 틀린다.
- 카테고리 분류 로직(가맹점명 → 카테고리 추론)을 만들지 마라. 이유: step 7에서 LLM이 담당하며, 규칙 기반 분류를 여기 두면 두 벌이 된다.
- 이상거래에 대한 자연어 설명 문구를 생성하지 마라. 이유: 해석은 step 7의 책임이다.
